# 番茄写作助手（Tomato Writer）

面向个人作者的**本地优先** VS Code 写作扩展，专为番茄小说短篇创作设计。支持男频、女频、悬疑三类短篇，覆盖从策划、文风、大纲到逐章生成、审校、人工审批的完整链路。

- **本地优先**：所有项目均为可查看、可备份的 UTF-8 TXT 文件，无账号、无云同步、无遥测。
- **AI 辅助但不越权**：AI 只生成候选稿，节奏、一致性与文风由系统审校，最终由作者批准正式稿。

## 核心原则

- 每本小说是一个独立项目，默认保存在“文稿/番茄写作项目”项目库中。
- 新项目的正文、策划、大纲和资产均为可直接查看和备份的 UTF-8 TXT 文件。
- API Key 使用 VS Code SecretStorage 保存，不写入项目或导出文件。
- AI 只生成候选稿，不能直接覆盖正式正文。
- 候选稿经过节奏、一致性和文风审校，由作者最终批准。

## 功能特性

**策划与文风**
- 分男频 / 女频 / 悬疑三条赛道，题材、视角、节奏等采用**选择式填写**（本地预设 + AI 候选，可手改）。
- 「AI 推荐子类型」：输入题材概念，AI 给出推荐的二级题材、写法取向与文风建议。
- 男频二级题材内置**写法策略卡**（脑洞向放开 / 写实向收敛），首句示例、书名公式、字数与对话比目标、常见坑一应俱全。

**剧情大纲**
- 按阶段维护每章目标、人物立场、关键事件、冲突、转折、情绪回报、伏笔、上下章衔接与章末钩子。
- 支持 AI 生成详细大纲结构。

**创作资产**
- 维护人物、世界观与伏笔，AI 生成时自动纳入上下文。

**写作与审批**
- 查看 AI 上下文，逐章生成候选稿；生成后可一键审校，通过硬指标闸门（字数、对话占比、题材目标、伏笔回收、AI 味评分）后才可批准为正式稿。
- 男频脑洞流自动嵌入当下网络热梗（每章至多 1 个）。

**审校与去 AI 味**
- 六维度「去 AI 味」硬约束写进生成 Prompt；审校输出 0–100 的 **AI 味评分（aiSmell）**，超标候选稿会被打回修订。
- 对话占比按题材策略动态判定（如男频脑洞 35–50%），不再是固定区间。

**统计与导出**
- 按项目统计写作进度，支持导出 TXT 或 Markdown。

## 使用

1. 执行“番茄写作助手：新建写作项目”。
2. 扩展会在默认项目库中创建小说文件夹；也可选择其他位置。
3. 从左侧“我的项目”选择小说，在“项目文件”中可直接展开正文、策划、资产等真实文本文件，单击即可用 VS Code 编辑器打开。
4. 在“策划与文风”填写本书独立标准（支持选择式填写与 AI 推荐）。
5. 在“剧情大纲”按阶段维护每章目标与钩子，也可让 AI 生成详细结构。
6. 在“创作资产”维护人物、世界观和伏笔。
7. 在“写作与审批”查看 AI 上下文，生成候选并批准正式稿。
8. 在“统计”导出 TXT 或 Markdown。

## 仓库结构

```
tomato-writer/
├── src/                    # 扩展宿主入口（TypeScript，编译到 out/）
├── packages/
│   ├── core/               # 核心逻辑：prompts、项目模型、TXT 编解码、指标、工作流
│   └── contracts/          # 跨包共享类型与协议
├── webview/                # React 18 + Vite 前端（开发期源码，构建到 dist/webview/）
├── tests/                  # 单元测试（vitest）
├── docs/                   # 产品 / 策略 / 需求文档
│   └── 测试报告/            # 各轮测试报告与测试产出
├── samples/                # 用扩展生成的示例小说项目（TXT 文本库）
├── media/                  # 品牌图标（SVG，非 emoji）
├── dist/                   # 构建产物（不进 git / vsix 外）
└── out/                    # 扩展编译产物（不进 git）
```

> 说明：`dist/`、`out/`、`node_modules/`、`*.vsix` 均被 `.gitignore` 排除；发布时仅 `dist/`、`out/`、`media/`、`package.json` 等进入 vsix。

## 技术栈

| 层 | 技术 |
|----|------|
| 扩展宿主 | TypeScript（commonjs）+ VS Code API，`fetch` 代理 AI 请求（绕过 webview CSP） |
| Webview | React 18 + TypeScript + Vite + zustand |
| 核心包 | npm workspaces 管理的 `@tomato-writer/core`、`@tomato-writer/contracts` |
| 构建 | `tsc`（扩展）+ `vite build`（webview）+ esbuild |
| 测试 | vitest |
| 打包 | `@vscode/vsce` |

## 本地开发

```bash
npm install
npm test          # 运行单元测试
npm run build     # 一键构建（核心包 + webview + 扩展）
```

- 按 **F5** 启动 Extension Development Host 调试。
- 改 webview 代码后执行 `npm run webview:build`，在扩展宿主窗口 `Ctrl/Cmd+R` 重载。
- 打包：`npm run package`（生成 `.vsix`）。

完整流程见 [`WORKFLOW.md`](./WORKFLOW.md)，架构见 [`ARCHITECTURE.md`](./ARCHITECTURE.md)，界面设计规范见 [`DESIGN.md`](./DESIGN.md)。

## 数据安全

新项目采用原子写入；批准候选稿前会在项目的 `备份/` 生成快照。旧版 `.md + JSON` 项目仍可原样使用，也可通过“迁移为易读 TXT”复制到项目库；迁移不会删除或改写源项目。仍建议将整个项目库纳入 Time Machine 或其他个人备份方案。

当前版本是本地单用户工具，不包含账号、云同步、多人协作或遥测。
