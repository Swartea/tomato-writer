# 番茄写作助手 · 内容资产升级 · 专家团任务简报

> 用途：把"番茄写作助手"这款 VS Code 扩展的内容/方法论资产，从 2024-era 老套路升级到 2026 番茄小说短篇真实打法。
> 状态：P0（AI 写作大脑）已落地，现需补齐产品"示范内容"与全局一致性。
> 读者：即将接手的内容策略专家 + 前端实现专家。

---

## 〇、一句话背景

这是一款**番茄小说「短篇」写作**的 VS Code 扩展（注意：是短篇，不是长篇）。它给作者一套写作工作台：6 个面板 + 一个 AI 引擎。我们要做的，是把这套产品里"教作者怎么写"的内容资产，按 2026 年番茄真实热门套路重做一遍。

---

## 一、系统到底长什么样（先对齐，免得专家瞎改）

| 面板 | 干什么 | 内容来源 |
|---|---|---|
| 开篇策划 | 5 步向导：题材→卖点→标题→开篇→字数 | AI 生成 + 硬编码示例库 |
| 写作编辑器 | 章节写作、实时字数、自动保存 | 作者自己写 |
| 大纲 | 主线/节奏曲线/分章细纲 | AI 生成 |
| 角色 | 人物卡 + 世界观 | 硬编码 demo 卡 |
| AI 助手 | 续写/润色/起名/灵感/主编评价/逻辑检查/AI味检测 | `aiService.ts` 里 8 个 prompt |
| 统计 | 字数/连续天数/目标 | 计算 |

**关键认知**：这套产品的"内容大脑"不在文档里，在代码里——
- `webview/src/aiService.ts`：8 个 AI prompt（卖点 / 书名 / 角色名 / 大纲 / 写作 / AI味检测 / 逻辑检查 / 主编评价），外加一个 `TOMATO_BASE_SPEC` 共享基座。
- `webview/src/App.tsx`：硬编码的**示例库**——题材卡描述、卖点范例、开篇 6 种模板、角色卡、demo 章节（"林小雨/顾寒川"两章）。

**作者真正看的内容** = 自己的稿 + 策划元数据 + 大纲/角色 + AI 生成物 + 统计 + 隐性教学示范（上面那套硬编码示例库）。后两类就是本次要升级的"内容资产"。

## 三、专家团待办（核心，按优先级）

### 🔴 P1（最高优先）—— 刷新 App.tsx 硬编码示例库
这是 P0 之后最该干的。底层 prompt 已经不分男女频了，但**界面里喂给作者的示范内容还是全偏女频/豪门**，等于"双重偏斜"，作者学不到男频/悬疑打法。

具体子项（都在 `webview/src/App.tsx`，用 Grep 搜 `题材`/`卖点`/`开篇`/`角色`/`林小雨`/`顾寒川` 定位）：
1. **题材卡描述**：补男频（都市脑洞/异能、赘婿战神、历史权谋/西幻领主）、悬疑脑洞的卡面文案与"糖"的定义（男频=打脸/信息差，女频=心动/被偏爱，悬疑=线索拼图）。
2. **卖点范例库**：当前 3 个示例 2 个言情，需补齐男频/悬疑的卖点示范。
3. **开篇 6 种模板**：当前范文是"林小雨雨中撞顾寒川"，需按题材各给一套（男频冲突钩、女频心动钩、悬疑线索钩）。
4. **角色卡 demo**：当前全古言柔美名，需补男频/悬疑人名与人物卡范式。
5. **demo 章节**：那两章"林小雨/顾寒川"示范，至少补一个男频开篇示范章（前 300 字出事、前 1000 字亮金手指）。

**改写标准**（和 P0 的 `TOMATO_BASE_SPEC` 对齐）：
- 前 300 字出事、前 500 字主角出场、前 1000 字金手指亮、首章 1500–2000 字。
- 题材分轨，绝不混用女频示范到男频场景。
- **禁 emoji**（DESIGN.md 铁律），用文字标记。
- 体现 2026 反套路金手指（冷门职业+异能 / 重生清算 / 摸鱼变强），别再用"废柴觉醒系统"老梗。

### 🟡 P2 —— 清内部矛盾
- 前 300 字 vs 前 500 字钩子口径统一（基座已定 300/500/1000，界面文案要跟）。
- 字数分档统一：短篇 3–5 万 / 悬疑 5–8 万 / 古言 8–12 万，界面与 prompt 对齐。
- "黄金三章"模板在界面和 prompt 里都不分题材——补分轨版本。
- 全局 `temperature` 0.8 是否降到 0.7（影响所有调用，需评估后再动）。

### 🟢 P3 —— 研究纠偏 + 品牌一致性
- 把 `番茄小说套路研究-2026.md` 从"长篇榜单"纠偏成"短篇专版"（短篇推荐逻辑、完读预期、字数结构和长篇不同）。
- **品牌偏差**：`DESIGN.md` 明令"品牌标用 tomato-icon.svg、禁 emoji🍅、导航禁 emoji"，但代码里 sidebar 用 🍅、导航和 AI 功能卡全用 emoji。逐处替换成 SVG/文字。

## 四、不能碰的红线 / 技术规范

1. **品牌铁律（DESIGN.md）**：禁 emoji，品牌标识用 `media/tomato-icon.svg`。所有新增 UI 文案、prompt 输出、示例库一律禁 emoji。
2. **2026 短篇硬指标**（写进基座，界面文案必须一致）：前 300 字出事、前 500 字主角出场、前 1000 字金手指亮、首章 1500–2000 字、章末三型钩（悬念留白/冲突升级/爽点预告）。
3. **题材分轨定义**：男频=打脸/信息差；女频=心动/被偏爱；悬疑脑洞=线索拼图感。任何示范内容必须标注适用赛道。
4. **改完必须跑 `npm run webview:build`**：tsc 零类型错误 + Vite 打包成功才算过。别只改不验。
5. **动 `App.tsx` 时注意调用方**：`SELLPOINT` 的 `{genre}` 在 404/696 两处已 replace，保留即可；`NAMING`/`BOOK_TITLE` 聊天路径直接拿 `input` 当消息、不传 genre，别给这俩加 `{genre}` 占位（会漏字面量）。
6. **非破坏性**：过程稿进 `_archive/`，别删历史文件。
