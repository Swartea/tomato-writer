## 六、迭代记录（证明硬指标闸门必要）

我作为 LLM 生成时，**前 5 轮均被闸门拦截**，直至第 6 轮全绿：

| 轮 | 第1章 | 第2章 | 第3章 | 主要违规 |
|----|-------|-------|-------|----------|
| 1 | 1253✅ / 28%❌ | 753❌ / 43%✅ | 793❌ / 39%✅ | 字数不足 + 对话比偏低 |
| 2 | 1331✅ / 31%❌ | 945❌ / 49%✅ | 848❌ / 40%✅ | 字数不足 |
| 3 | 1404✅ / 32%❌ | 964❌ / 51%❌ | 995❌ / 42%✅ | 字数不足 + 对话比超上限 |
| 4 | 1450✅ / 32%❌ | 1113❌ / 44%✅ | 1169❌ / 38%✅ | 字数不足 |
| 5 | 1525❌ / 34%❌ | 1178❌ / 42%✅ | 1200✅ / 37%✅ | 字数超 + 对话比偏低 |
| 6 | 1498✅ / 36%✅ | 1208✅ / 41%✅ | 1200✅ / 37%✅ | 全绿 |

**发现**：1200–1500 字 + 35–50% 对话比这个窗口**很窄**，真实模型若无 token 预算循环，极易落在窗外；硬指标闸门（revisedContent 再审）是必需的，且可能需要 **>2 轮**修订才能稳定达标。这解释了为何上一版报告「全达标」却是假象——它没接题材策略、也没真测。

## 八、待办 / 已知问题

1. **双视角评审 UI 未实现**：方案第 6 节的「番茄读者划走风险% / 番茄小编过稿概率%」按钮尚未落地，本报告对应列为人工自评。
2. **模型响应慢根因未定位**：非流式 + 正文/审校双请求易超时，真实环境需区分模型慢 vs 链路问题（建议改流式 + 合并请求）。
3. **自动修订稿偏差量化缺失**：本轮由我手动迭代，未统计每章人工改字数；真实环境应记录 revisedContent 与 content 的差异度。

5. **打包收紧**：`.vsix` 当前会带进根目录 `*.md` / `design/` / `_archive/` 等非运行必需文件（`.vscodeignore` 未排除），发布前应收紧。
