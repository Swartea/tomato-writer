- **日期**：2026-07-29
- **版本**：tomato-writer 0.4.1 + prompts `PROMPT_VERSION = 2026.07-v3`
- **测试方式**：白盒测试。用 esbuild 编译真实 `packages/core/src/prompts.ts` + `metrics.ts` 为 Node ESM 模块，直接调用真实函数（`brainstormPrompt / subtypePrompt / outlinePrompt / writingPrompt / reviewPrompt / buildContext / dialogueTarget / candidateViolations / dialogueRatio / countCharacters`），由测试者按真实 prompt 充当 LLM 生成产出，再用真实 metrics 函数验证硬指标。

## 一、文案功力测试

### 1.1 选题脑洞（brainstorm + subtype）✅ 通过

| 产出项 | 结果 | 校验 |

| 卖点 | "摸鱼被老板当场抓包，他等着开除通知，老板却递来顾问合同，说该摸的底摸完了吗"（33 字） | 含身份+冲突+反差 ✅；无空词 ✅ |

**放开档 vs 收敛档对比**：收敛档灵感"北漂回老家过年"在 male 赛道下，brainstormPrompt 仍注入 TRACK_RULES.male（脑洞放开文案），与收敛意图冲突——详见逻辑问题 #1。

### 1.2 大纲逻辑（outline）✅ 全通过

| 校验项 | 结果 |

**结论**：outlinePrompt 的结构要求（8 条硬性规则 + 字段含义）能有效驱动因果链自洽、伏笔配对、闭环收束。

### 1.3 续写正文（writing）⚠️ 去 AI 味通过，硬指标首轮落窗

按真实 `writingPrompt`（都市脑洞 / 第 1 章）充当 LLM 生成正文，用真实 metrics 实测：

| 2. 反转有起伏（非均匀打卡） | 人工判断 | ✅ |

### 1.4 审校（review）✅ 机制有效

## 二、逻辑链路审查

### 2.1 硬指标闸门（candidateViolations）✅ 正确拦截

| 用例 | 输入 | 闸门报出 |
|------|------|----------|
| 超字数 | 1600 字 | ✅ "原候选长度1600字，要求1200—1500字" |
| 不足字数 | 1 字 | ✅ "原候选长度1字" |
| 对话比偏低 | 1300 字 / 0% | ✅ "原候选对话占比0%" |
| 原稿差+修订稿好 | 原稿1403字0% / 修订850字29% | ✅ 分别报出修订版字数不足、原稿对话比0%、修订对话比29% |

**结论**：闸门对原稿和修订稿**分别校验**，且按题材目标（非全书平均）判定，逻辑正确。

### 2.2 伏笔追踪（buildContext 过滤）✅ 全通过

`buildContext` 的伏笔过滤逻辑：`status !== 'paid' && plannedPayoffChapter <= chapter.order + 2`

| 用例 | 预期 | 结果 |
|------|------|------|
| 第 6 章（order+2=8）带 f1（回收 6≤8） | 应带 | ✅ |
| 第 6 章带 f2（回收 7≤8） | 应带 | ✅ |
| 第 6 章排除 f3（status=paid） | 应排除 | ✅ |
| 第 1 章（order+2=3）不提醒 f1（回收 6>3） | 应排除 | ✅ |
| 第 1 章不提醒 f2（回收 7>3） | 应排除 | ✅ |

**结论**：伏笔"到期提醒"逻辑正确——只提醒 2 章内要回收的，已回收的排除，远期的不提醒。

### 2.3 对话比口径 ⚠️ 分母含空白

`dialogueRatio` 用 `text.length`（**含空白/换行**）做分母，而 `countCharacters` 用去空白。两者口径不同：

- 正文段落换行多时，`text.length` 变大，对话比被**压低**。
- 实测：`dialogueRatio('他说"你好啊"然后走了。她说"再见"。')` = 47%（9/19，含引号字符）。
- 闸门和审校都用 `dialogueRatio`，口径一致，不会误判。但若正文大段无对话叙述+多换行，实际对话占比可能"体感达标但算出来不达标"。

**风险等级**：低。口径一致不影响闸门公正性，但可能让作者困惑"明明对话很多为什么报不达标"。

### 2.4 JSON 解析（parseModelJson）⚠️ 多对象截断风险

`parseModelJson` 逻辑：剥离 `<think>` 标签 → 剥离 ``` 围栏 → 取首个 `{`/`[` 到末尾 `}`/`]`。

| 场景 | 结果 |
|------|------|
| 模型返回 `<think>思考</think>{...}` | ✅ 剥离思考链 |
| 模型返回 ` ```json\n{...}\n``` ` | ✅ 剥离围栏 |
| 模型返回 `好的，结果如下：{...}` | ✅ 提取 JSON |
| 模型返回两个 JSON 对象 `{...}解释{...}` | ⚠️ `lastIndexOf('}')` 取最后一个，可能截断错误 |

**风险等级**：中。多数模型不会返回两个对象，但流式输出截断重连时可能出现。

## 三、发现的问题

### 🔴 P1：赛道规则与题材策略冲突（逻辑矛盾）

**位置**：`prompts.ts` `TRACK_RULES` + `writingPrompt / buildContext / planningPrompt / outlinePrompt`

**现象**：`TRACK_RULES.male` 永远输出"男频脑洞：设定可夸张、反套路、开局即炸…"（放开档文案），**无论选了哪个二级题材**。当 genre=都市日常/现实题材/乡村生活（收敛档）时，prompt 同时注入：

- 赛道规则："设定可夸张、反套路、开局即炸"（放开）
- 题材策略："收敛档：避免开局无敌、龙傲天、标题党"（收敛）

两个**矛盾指令**同时出现，模型会困惑——收敛档题材实际上收不住。

**根因**：`TRACK_RULES` 按 genreTrack（male/female/mystery）分轨，把整个男频赛道都定义为"脑洞放开"。但 `GENRE_TACTICS` 里有 3 个收敛档题材（都市日常/现实题材/乡村生活），它们的 `core` 写了"收敛档"，却被赛道规则覆盖。

**修复建议**：`TRACK_RULES.male` 改为中性描述（"男频：爽点来自能力/信息差/局势逆转/降维碾压；放开或收敛由题材策略决定"），把"设定可夸张/开局即炸"下沉到脑洞向题材的 `GENRE_TACTICS.core` 里（已经有了）。或者在 `writingPrompt` 里判断：若题材 tactic 含"收敛档"字样，不注入 TRACK_RULES.male 的放开文案。

### 🟡 P2：对话比口径含空白（体验问题）

**位置**：`metrics.ts` `dialogueRatio`

**现象**：分母用 `text.length`（含换行/空格），正文换行多时对话比被压低。作者体感"对话很多"但算出来不达标。

**修复建议**：改用 `countCharacters(text)`（去空白）做分母，与字数口径统一。需同步调整 `reviewPrompt` 里报告的 dialogueRatio。

### 🟡 P3：伏笔铺设依赖章纲，buildContext 不提醒"本章应铺设"

**位置**：`prompts.ts` `buildContext`

**现象**：`buildContext` 只提醒"即将到期需回收"的伏笔（`plannedPayoffChapter <= order+2`）。第 1 章铺设的伏笔在第 1 章写时不会被提醒——除非章纲（`chapter.outline`）里写了。若大纲生成时伏笔标记遗漏，后续链路静默断裂。

**风险等级**：中。依赖 `outlinePrompt` 正确标记伏笔 + `outlineWritingBrief` 正确转换。已有测试覆盖转换逻辑，但无"伏笔必须出现在对应章纲"的断言。

**修复建议**：`buildContext` 额外注入"本章 planned 的伏笔"（`plantedChapter === chapter.order` 的 planned 状态伏笔），让 AI 写正文时知道要铺。

### 🟢 P3：parseModelJson 多对象截断（边界风险）

**位置**：`parsing.ts` `parseModelJson`

**现象**：`lastIndexOf('}')` 在多 JSON 对象场景可能取错闭合位置。

**风险等级**：低。正常模型不会返回多对象，但建议加防护。

> 续写正文 3 项 FAIL 不是软件缺陷——是闸门**正确拦截**了我充当 LLM 的首轮生成（字数850/对话比22%落窗），验证了硬指标闸门的必要性和"窗口极窄"的已知发现。

**文案功力结论**：选题脑洞、大纲逻辑、审校机制均达标；续写正文的去 AI 味约束有效（六维度全通过，aiSmell=28），硬指标需多轮修订才能稳定达标（与既有迭代记录一致）。

**逻辑链路结论**：闸门、伏笔追踪、JSON 解析核心逻辑正确；发现 1 个 P1 逻辑矛盾（赛道规则与题材策略冲突）需修复，2 个 P2/P3 体验/边界问题建议优化。
