# 内部 Skill 生产力评估报告

> 测试对象：内容创作专家挂载的 5 个内置 skill
> 对照基准：番茄写作助手项目（男频脑洞 / 去AI味六维度 / 硬指标闸门 / 题材策略卡 / 伏笔追踪）
> 日期：2026-07-31

---

## 一、测试方法

1. 读取 5 个内置 skill 的 `SKILL.md` 定义，梳理各自职责与触发场景。
2. 以番茄写作助手项目的**真实需求**为基准，评估每个 skill 的关联度与架构对接度。
3. **实战实测**：用 humanizer 方法论处理一段 AI 味番茄男频文案，产出去味前后对照，并对照项目 prompts 的"去AI味六维度"评估覆盖度。

> 项目"去AI味六维度"（来自 `packages/core/src/prompts.ts` 的 `aiSmell` 评分依据）：
> ①套路化表达 ②逻辑过于完美缺真人细节 ③节奏均匀无变化 ④情感刻板 ⑤长句堆砌 ⑥章末金句文艺腔

## 二、五个 skill 逐一研判

### 1. anti-distill — 反蒸馏 / 脱敏
- **实际职责**：清洗 skill 文件，看起来完整但抽掉核心商业秘密（触发词 `/anti-distill`、`反蒸馏`、`帮我清洗一下这个 skill`）。是一个**防御性/合规工具**。
- **与项目关系**：❌ 零关联。既不生成内容，也与网文写作无关。
- **问题**：系统提示里把它标注为"去AI味 — 清除 AI 写作痕迹"，**描述与实际完全不符**，会误导使用者。
- **结论**：不属于内容生产力工具，评分 1。

### 2. humanizer — 去AI味（24 模式）
- **实际职责**：基于 Wikipedia《Signs of AI writing》的 24 种 AI 写作模式（膨胀象征、宣传语言、浅层分析、破折号滥用、三一律、AI 词汇、否定平行、标题大写、emoji、卷曲引号……），改写去味并"加灵魂"。方法论成熟专业。
- **与项目关系**：✅ 方法论与项目"去AI味六维度"一致，但语料偏**英文/百科非虚构**；番茄是**中文网文**场景。
- **结论**：高质量通用去AI味工具，可作审校外挂；对中文网文覆盖有 gap。评分 7。

### 3. novel-writer — 章节提示词构建器
- **实际职责**：Python CLI（`scripts/write_chapter.py`），读 Markdown 大纲 + `style.yml` + `characters/*.yml`，**生成 LLM 提示词**（不直接产出正文）。
- **与项目关系**：⚠️ 架构完全不对接——它有自己的 `--book-dir` 文件约定，而项目是 VS Code 扩展 + JSON 存储（`readable-txt` 布局）。功能上与项目 `writingPrompt` **重叠**（都是"大纲+风格+角色→正文提示词"）。
- **结论**：重复且无法对接项目运行时，易与项目自带能力混淆。评分 3。

### 4. novel-writing — 长篇网文创作技能包
- **实际职责**：解决长篇连载 7 大痛点（上下文丢失 / 文风不一致 / 设定冲突 / 节奏失控 / 多线混乱 / 质量不稳 / 读者反馈内化）。含 `novel init/setting/outline/write/check/conflict/feedback` 工作流、伏笔追踪、文风指南、状态文件。
- **与项目关系**：⚠️ **痛点与番茄项目高度重合**（伏笔追踪 / 文风档案 / 设定冲突 / 质量闸门），但它是**独立的 CLI 体系**，文件约定（`settings/`、`tracker/`、`state.json`）与项目 ProjectData 不对接；且 SKILL.md 是规范文档，CLI 是否真实实现待确认。
- **结论**：思路可借鉴，但作为"项目生产力"需重写为对接 ProjectData 的模块，否则只是另一套平行系统。评分 5。

### 5. minimax-docx — Word 文档生成
- **实际职责**：基于 OpenXML SDK (.NET) 的专业 Word 文档生成/编辑（三套流水线 + XSD 校验门 + 13 种美学配方）。功能很强、很完整。
- **与项目关系**：⚠️ 项目产出是 `txt/md/json`，**不是 docx**。除非用户要把小说导出成投稿 Word 稿，否则关联度低。
- **结论**：通用文档生产力强，但不在番茄项目主路径上。评分 2。

## 四、humanizer 实战实测（去AI味对照六维度）

**去味前（典型 AI 味番茄男频文案，埋雷版）：**
> 陈默站在天台边缘，夜风掠过他的脸颊。他深吸一口气，心中涌起一股莫名的悲凉——这是他三十年来最绝望的夜晚。就在这时，手机响了，是老板发来的最后通牒。陈默没有犹豫，果断地做出了选择。他不仅要还清三百万债务，更要证明自己的价值。这一步，不仅是人生的转折，更是一次彻底的重生。命运的齿轮开始转动，属于他的时代，终于到来。

**去味后（应用 humanizer 方法论）：**
> 陈默趴在天台栏杆上，风把烟吹歪了。手机震了一下，老板发来最后通牒：再不给钱就找人。他想了半天，把烟按灭，回了一句"钱明天到"——其实卡里就剩两百块。

**对照项目六维度：**

| 六维度 | humanizer 覆盖 | 说明 |
|--------|--------------|------|
| ①套路化表达 | ✅ 已改善 | 删掉"命运的齿轮/时代到来"套路 |
| ②缺真人细节 | ✅ 已改善 | 加"卡里剩两百块"的具体窘境（humanizer"加灵魂"间接覆盖） |
| ③节奏均匀无变化 | 🟡 部分 | 句式变短变口语，但 humanizer 无显式规则 |
| ④情感刻板 | 🟡 部分 | 从"悲凉"套路到"想半天按灭烟"的具体焦虑，靠"加灵魂"间接改善 |
| ⑤长句堆砌 | ✅ 已改善 | 拆长句、去宣传腔 |
| ⑥章末金句文艺腔 | ✅ 显著改善 | 直接删除章末金句 |

**实测结论**：humanizer 能搞定 6 维度里的 ①⑤⑥ 大部分 + ②③④ 部分；但 ③④ 主要靠"加灵魂"间接改善，不如项目六维度显式对症。且 humanizer 的 24 模式里大量条目（标题大写、卷曲引号、emoji 装饰、知识截止免责、协作套话）在**中文网文**几乎用不上——中文网文特有的"套路化爽点""信息密度低""章末文艺腔"才是重点。估算 humanizer 对中文网文的去味覆盖约 **40%**。

## 五、总体结论

这套内置 skill 是**通用内容创作工具箱**，并非为"番茄男频网文 VS Code 扩展"定制。生产力适配度分化明显：

- **真正直接有用**：`humanizer`（去AI味），但需补"中文网文"维度，且正文去AI味应以项目自带六维度为准。
- **高度重叠但架构不对接、易混乱**：`novel-writer` / `novel-writing`——项目已有更对症的实现（`writingPrompt` / `buildContext` / 伏笔追踪 / 六维度 / 硬指标闸门），再挂一套平行 CLI 体系只会重复和冲突。
- **误标 / 误导**：`anti-distill` 被系统提示标成"去AI味"，实际是反蒸馏脱敏，与写作无关。
- **场景外但通用有用**：`minimax-docx`（Word），除非导出投稿稿，否则主路径用不上。

**一句话**：当前 skill 组合作为"内容创作专家通用工具箱"合格，但作为"番茄项目生产力"不合适的部分偏多，需要收口 + 补中文网文专用能力。

---

## 六、改进建议

1. **修正系统提示描述**：把 `anti-distill` 从"去AI味"更正为"反蒸馏 / 脱敏（清洗 skill 文件保护商业秘密）"，消除误导。
2. **钉清 novel 类 skill 定位**：在 `novel-writer` / `novel-writing` 的说明里明确"通用网文 CLI，非番茄项目组件"，避免与项目自带能力混淆或重复调用。
3. **humanizer 作审校外挂**：项目正文去AI味以 `prompts` 六维度为准；humanizer 用于英文/通用文案或作为二次润色。
4. **建议新增"中文网文去AI味"专用 skill**：基于项目六维度（套路化爽点 / 节奏均匀 / 情感刻板 / 章末文艺腔 / 信息密度），覆盖 humanizer 对中文网文的 gap。

## 七、关键发现速览

- 🔴 `anti-distill` 实际是反蒸馏脱敏，系统提示误标为"去AI味"。
- 🟡 `novel-writing` 痛点与项目高度重合，但 CLI 体系与项目 ProjectData 不对接。
- 🟡 `humanizer` 24 模式对中文网文去味覆盖约 40%，需叠加项目六维度。
- ⚪ `minimax-docx` 强大但偏离项目 txt/md/json 主产出。
